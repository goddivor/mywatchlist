# Project state — MyWatchList

Cap: 80 lines. Rewrite in place; history lives in git and `docs/DECISIONS.md`.
## Where we are (2026-10-27)
- Porting every DailyAL feature (ref `upstream/2026.2.6+108`) into MWL, adapted to BLoC + multi-tracker, redesigning weak UI and fixing bugs on the way.
- Work is split into 38 units (`work/INDEX.md`), built in parallel with the multi-agent-build tooling (`tools/mab/`, `tools/mab.config`), coordinated on GitHub (goddivor/mywatchlist, base `dev`, `master` owner-only).
## Gate
- `tools/heavy.sh tools/verify.sh`: pub get, flutter analyze, flutter test, dart analyze mwl-api (machine-wide lock) (green since `gate-fix`; `flutter test` = offline smoke tests, about 10 s). Test layout: `test/smoke/` + `test/helpers/` (`pumpInApp`, `htmlFixture`, `forbidNetwork`), then `test/units/<unit-id>/` per unit. `verify.sh` first runs `tools/l10n/build.sh` (`S` is a build output, see CLAUDE.md).
- Localization (`l10n-pipeline`): base ARBs (DailyAL, 11 locales) frozen in `lib/l10n/`; each unit adds keys in `lib/l10n/units/<unit-id>/`; `tools/l10n/build.sh` merges, validates, generates `lib/generated/l10n.dart` + `intl/` (git-ignored).
## Preferences contract and dependencies (`deps-prefs-contract`)
- `lib/user/preferences/` (barrel `preferences.dart`): `PreferencesBloc` (state `AppPreferences` = `general`, `content`, `list`, `notifications`), one event per group with a `copyWith` updater, `PreferencesReset`, `PreferencesReloaded`; non-widget read `Preferences.current` / `Preferences.general`…; stored as one JSON per group (`prefs_*_v1`), legacy `timezone_pref` migrated.
- Language stays in `LanguageBloc`, theme/font/background in `ThemeBloc`, home layout in `HomePreferencesBloc`; `UserPreference` keeps MWL-only device settings. Accent (`theme-seasons`, docs/THEME.md): Material You, else "Auto (season)" (default; background season gives DailyAL's pink / deep orange / brown / light blue), else the picked colour; new install = Fall + Brown.
- Every dependency of the queued units is in `pubspec.yaml` (pins listed in the PR closing issue #29); manifest has notification, exact alarm, boot, calendar and install-packages permissions, the notification receivers, a FileProvider and the myanimelist.net VIEW filter (`autoVerify=false`, #132); pubspec `version: 2026.10.1+1`, font family `DubStatus`. `main` starts `DeepLinks.start()` next to the OAuth listener; `NotificationService.init()` is called from `main`.
## App shell (`app-shell`)
- Cross-unit navigation: `lib/utils/app_routes.dart` (`AppRoutes.openSettings/openSettingsPage(SettingsSection)/openAbout/openBookmarks/openCalendar/openSearch/openUserProfile/openUserStats/openContent/openLogin/openManageAccounts/openSidebar/signInAgain/openFromNotification`); `SettingsSection` (title, description, icon) in `lib/pages/settings/settings_section.dart`.
- Stubs (`ComingSoonPage`): 9 settings pages, bookmarks, calendar, user profile/stats; their units replace the body.
- Home shell: sidebar = end drawer (`AppRoutes.openSidebar` from any tab), startup page pref, only the current tab built unless `keepPagesInMemory` (then lazily kept), "session expired" snackbar for any tracker, notification payload `anime:<id>|manga:<id>|calendar|bookmarks`.
- Back in the shell (`ShellBackScope`, #92): closes the sidebar, then returns to the home tab, then on the home tab asks for a second Back within 2 s before leaving; the sidebar swipe zone is the system back-gesture inset + 24 dp. Signed-in users get "Add an account" in the sidebar (login page in add mode, #88).

- `lib/screens/MAL/detail/`: `detail_screen.dart`, `detail_data.dart` (immutable snapshot, incl. schedule links and next episode), `detail_sections.dart` (registry in the `ContentPreferences` order, `Dh_Tab_*` labels), `sections/`, `header/`, `actions/`, `tabs_customizer.dart`, `pages/`. `contentdetailedscreen.dart` re-exports it.
- Header (`header/`): fixed extent, 2-line title (long press copies), cover + title language switch + More Info, `ScoreReveal` score, LiveChart countdown chip (pref `showCountdownOnDetail`), faded background (pref `showDetailBackground`). App bar: search, bookmark, overflow (share, browser, More Info, search by genre, customize sections). `Dh_*` strings en + fr_FR. Related (`detail-related-graph`): `RelatedAnimeWidget` (tabs per relation, view-all grid `RelatedGridScreen` with list statuses, graph button for anime) and `AnimeGraphScreen` in `lib/widgets/graph/` (backend `getAnimeGraph`, graphview Sugiyama built once, fixed-size nodes, long-press selects, share as branded PNG through `RepaintBoundary`); strings `Rg_*`. `related_section.dart` passes `category` and `title` (manga pages have no graph button).
- Resilience (`detail-resilience`, `detail-polish`): every section (News included) ends in content, an empty state or an error with Retry (`SectionMessage`, `sections/section_states.dart`). `JikanFallbacks.race` (`lib/services/api/Jikan/jikan_fallbacks.dart`) runs Jikan, starts the fallback after 3 s (at once when Jikan fails or the client skips it) and gives up at 12 s: reviews (`ReviewsFeed`) vs mwl-api `reviews`, forum (`JikanApi.getAnimeForum`) vs MAL's forum page, cast vs mwl-api `content/characters`, score stats vs MAL's stats page (`ContentStatsSource`, then MAL's mean/rank), news vs MAL's `<category>/<id>/_/news` page parsed on the device (`MalNewsPage`); user updates have no other source. Characters, staff and reviews use DailyAL's layout: `CastPicture` portraits (rounded outer corners, no shadow, round placeholder), review cards 320 dp with "Show more…", `ReviewsListScreen` (view all); user pictures stay `RoundAvatar`. FAB and Stats chart take the status tokens; tab taps align the section under the pinned bar; header numbers follow the locale. Strings `Res_*`, `Dp_*`.
- More info (`detail-more-info`): `MoreInfoWidget` (`isModal` = owns its scroll view; the dialog in `actions/more_info_modal.dart` uses it, one scroll view): tonal cards, every chip is a link: studio, magazine, genre (search entry points), author (`CharacterScreen` person), season (`bySeason`), media type (ranking, plain text when no ranking exists). Empty fields hidden; status, rating, source, dates, duration translated; strings `Mi_*` (en + fr_FR).
## API layer (`api-prefs`)
- Jikan: `JikanClient` (throttle, in-flight sharing, 5 min cache, 429 backoff, 12 s timeout then 30 s fail-fast, `resetReachability()` on Retry, `JikanUnavailable`; `instance` replaceable in tests); MAL: `nsfw=` from the pref (the user's own `/users/@me/animelist|mangalist` always `nsfw=1`, #97), timezone pref in airing helpers, `MalApi.isUnderMaintenance()` (60 s cache) for home wiring, full `MyListStatus` + `save*ListStatus` with text dates.

## Accounts (`accounts-ux`)
- No picker, no "Continue": `AccountBloc` follows `UserManager` (sign in, sign out, dead session) and owns the active account; the first tracker that connects becomes active, signing out of the active one activates the next, `resolveSelection` (`account_selection.dart`) is the pure rule.
- One list everywhere: `AccountsPanel` of `TrackerTile`s (connected = radio, tap switches; expired = "Sign in again"; connecting = Cancel; disconnected = Connect). Used by Settings > Accounts (`ManageAccountsPage` is the same page), the avatar switcher (tap switches and closes), `LoginPage` (first run opens the home by itself; add mode switches to the new account and closes) and the intro page.
- `TrackerActions` (connect, cancel, sign out, switch) is the only caller of the auth classes; Kitsu has its own translated dialog with inline errors; `KitsuAuth.signInWithKitsu` ends any failure unauthenticated (#88). Sign out (`RemoveAccountEvent`) clears that tracker's `ListStatusCache`, `LogoutEvent` all of it (#97).
- One `AuthStatus` (base_user.dart, re-exported by user.dart); `needsReLogin` persists across restarts and `clear()` resets it.
- Strings: `Acc_*` in `lib/l10n/units/accounts-ux/` (en + fr_FR).
## Calendar (`calendar`)
- `CalendarScreen` (`lib/screens/calendar/`, `AppRoutes.openCalendar`): 7-day strip from today, list-status chips (All, Watching, Plan to Watch, 3-state In list / Not in list; hidden with a hint when the active account is not MAL), episode tiles with countdown, "now" rule, add-to-calendar sheet (device calendar with weekly recurrence, `.ics` save or share). Times follow the timezone pref; the app bar menu changes it. Logic in `lib/widgets/calendar/`: `CalendarCubit` (LiveChart schedule joined with the MAL season for covers, episode totals and list status), `calendar_logic.dart` (zones, week grouping, filters), `calendar_ics.dart` (RFC 5545 builder), `calendar_export.dart`. ## Backend (mwl-api)
- `backend-parsers` ported DailyAL's page parsers (`PageParsers`, typed `*Html` models) and routes: `content/characters`, `character|people/*id/pics`, `characters`, `people`, `magazines`, `studios`, `clubs?id=`, `clubs/type`, `search/all`; `reviews`, `users/about` parsed; `schedules` = LiveChart (`source=jikan` for the old proxy).
- Invalid parameters (unknown season, non-numeric id or year, missing `q`/`id`…) answer 400 via `BadRequest` (#72).
- Typed client methods on `MwlApi` (listed in the backend-parsers PR body, issue #27); HTML parsed off the UI isolate. `content/stats?id=&category=` parses MAL's `/<category>/<id>/x/stats` page (score votes 1-10 + status counts, `ContentStatsHtml`); `MwlApi.getContentStats(id, category)` returns null on failure or after 15 s (#134), for Score Stats without Jikan. Explore feeds (`profile-tabs`): `MwlApi.getGlobalRecommendations` (route `recommendations/recent`, MAL `recommendations.php?s=recentrecs`) and `getInterestStackList` (stacks listing is `/stacks/search?type=`, the old `/stacks?type=` URL is a hub page with no list); both null after 15 s or on failure.

## Cross-tracker sync (`sync-dialog`)
- `CrossTrackerWidget` (same constructor) lists the other signed-in trackers; each card loads on its own (link, then entry, in parallel) and offers Link, Edit, Sync, Unlink, Remove. Links are found automatically by MAL id (AniList `idMal`, Kitsu mappings, Simkl `mal:<id>`); unlinking sticks.
- Sync dialog (`lib/widgets/user/sync/sync_dialog.dart`): reads both sides when opened, shows what each would copy, runs MAL to tracker or tracker to MAL, Cancel always available (no write starts after a cancel). Empty fields never erase the target.
- Clients (`tracker_clients.dart`) go through `BaseUser.sendAuthenticated`; AniList scores use `score(format: POINT_10_DECIMAL)` to read and `scoreRaw` to write, Kitsu half points, MAL rounds to whole points. Simkl: anime only, status and score only.
- Editor sheet (`tracker_entry_editor.dart`) edits the tracker's own entry (status, score, progress, volumes, dates) and creates it when absent. Strings: `Sync_*` in `lib/l10n/units/sync-dialog/` (en + fr_FR). Callers drop the row on `SyncEntry.isRemoved` (AniList and Kitsu list adapters return `ListEditRemoved`, `CrossTrackerWidget` clears the card). Notifications (`tracker-followups`): the planner follows the active tracker; `NotificationService.init` listens to `UserManager` and replans when the feeding account changes (not at startup); the settings notice says "connect an account" only when none feeds the reminders (`Notif_Needs_Account`). Simkl's list page passes `categories: ['anime']`.
